# Steward: GitHub, PR, CI, merge

## Công cụ

- Trong sandbox cloud **không có `gh`**. Dùng các tool MCP `mcp__github__*`: `create_pull_request`, `pull_request_read` (`get_check_runs`), `merge_pull_request`, `issue_write`, `add_issue_comment`.
- Theo dõi PR bằng `subscribe_pr_activity`. Sự kiện CI và review sẽ tự đánh thức session. Không poll bằng `sleep`.
- Push: `git push -u origin <branch>`. Lỗi mạng thì thử lại tối đa 4 lần, chờ 2s, 4s, 8s, 16s.
- **Tag:** proxy chặn push tag (`send-pack: unexpected disconnect`). Đừng thử nhiều lần. Hướng dẫn chủ dự án:
  1. mở Releases → Draft a new release;
  2. Choose a tag `vX.Y.Z` → Create new tag;
  3. Target: chọn commit merge (đưa SHA đầy đủ cho tag cũ);
  4. tiêu đề và mô tả: dán link checkpoint dạng `…/blob/vX.Y.Z/docs/releases/vX.Y.Z.md` hoặc dán nội dung file.

## Nhánh và PR

- Nhánh mặc định `master`. Làm trên `feature/*` hoặc `fix/*`, một PR cho mỗi đợt.
- Nếu PR của nhánh đã merge: tạo lại nhánh từ `master` mới nhất. Không chồng commit lên lịch sử đã merge.
- **Tiêu đề PR:** `vX.Y.Z: <tóm tắt tiếng Việt>`.
- **Body PR:** viết tiếng Việt.
  - nhóm thay đổi theo trang hoặc vùng;
  - `Closes #N` cho từng issue xong, `Refs #N` cho issue còn mở;
  - mục **Kiểm tra** ghi lệnh đã chạy, số bench, những gì kiểm bằng Playwright, những gì chỉ kiểm bằng mock;
  - cuối body là các dòng attribution mà session yêu cầu.
- Mọi comment trên GitHub kết thúc bằng footer:
  ```
  ---
  _Generated by [Claude Code](https://claude.ai/code)_
  ```
- Hạn chế comment. Chỉ comment khi thật cần.

## Theo dõi đến khi merge

1. Sau khi tạo PR: `subscribe_pr_activity`.
2. **Khi có sự kiện CI:** đọc `get_check_runs`.
   - `build` = success (job `deploy` bị skip trên PR là bình thường) và head SHA khớp `git rev-parse HEAD`: merge bằng `merge_pull_request` (method `merge`, `expectedHeadSha`).
   - CI đỏ: đọc log, tái hiện cục bộ, sửa và push. Không skip hay tắt test, không push commit rỗng.
3. **Trước khi merge:** `git status` phải sạch, không có thay đổi cục bộ chưa push.
4. **Review:** việc nhỏ thì sửa luôn. Việc lớn thì trả lời đề xuất và hỏi chủ dự án.
5. **Sau merge:** session tự hết theo dõi. Merge vào `master` tự deploy Pages (job `deploy`). Báo cho chủ dự án link bản chạy và việc tạo tag.

## CI (`.github/workflows/ci.yml`)

- Chạy theo thứ tự `npm ci` → typecheck → test → build → bench (Playwright, `vite preview :4173`, ngân sách `bench/budget.json`).
- Trên `master` có thêm: sinh tiếp height tiles z14 (cache giữa các lần chạy, cron hằng ngày) rồi deploy Pages.
- Đổi URL trang thì sửa luôn `bench/run.cjs`. Bench mở `/openstreetmap/?demo&bench`.
- Thêm dependency: chạy `npm i` để cập nhật `package-lock.json` (CI dùng `npm ci`). Kiểm tra peer dependency không làm `npm ci` lỗi.

## Issue

- Tạo bằng `issue_write`, gắn label `feature`/`bug` và `status: ready` sau khi PO và TL đồng ý.
- Đóng: qua `Closes #N` trong PR. Nếu đóng tay thì đặt `state_reason: completed`.
- Issue #1 (Roadmap) luôn mở.
