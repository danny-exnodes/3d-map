# Toy Style Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the three display styles of the OpenStreetMap builder (Có màu, Đơn sắc, Siêu thực) with a single cozy "Toy" style whose four moods (A morning, B noon, C golden hour, D night) follow the day/night cycle, chosen from a mood picker.

**Architecture:** The moods are light-only keyframes blended from the sun state (`src/scene/moods.ts`), so one fixed toy palette (`src/scene/toyPalette.ts`) works all day. Ordinary houses keep GPU instancing. Their rounded unit meshes carry per-vertex corner anchors, and the vertex shader places each vertex at `corner × (halfSize − r) + offset`, so bevels keep their real size on every house; the same maths runs on the CPU for GLB export (`src/scene/toyGeometry.ts`). Tilt-shift is added to the existing composer.

**Tech Stack:** TypeScript, Three.js 0.186 (EffectComposer, `HorizontalTiltShiftShader` and `VerticalTiltShiftShader` from `three/examples/jsm/shaders/`), Vite, Vitest. The geometry worker serialises through `src/scene/serialize.ts`.

**Spec:** `docs/superpowers/specs/2026-10-27-toy-style-design.md`

## Global Constraints

- Before code: a GitHub issue for this work with label `status: ready` (repo CLAUDE.md, issue #1). Work on `feature/toy-style`, open a PR, merge after green CI.
- Before every push: `npm run typecheck && npm test && npm run build && npm run bench`.
- Bench budget (`bench/budget.json`): `triangles` 500000 (raised from 300000 in this work), `drawCalls` stays 40. CI fails beyond +20%.
- Heights, footprints and positions are never changed; no height squashing.
- Nothing a prototype draws crosses its true footprint: plinth = footprint, body inset 0.3 m, roof overhang reaches the footprint edge and no further.
- Rounded geometry: 1–2 bevel segments with smooth normals.
- The page opens at the area's real current time; the mood is not stored between visits.
- UI text is Vietnamese. The Google page (`src/google/`) is not touched.
- Pixel mode, rain, space view, the height-source view, traffic, the location pin, the building card, offline maps and GLB export keep working.

## Review Focus

1. **Real OSM row houses sharing walls**: neighbouring prototypes must not overlap or flicker. Covered by `toy geometry stays inside the footprint` (Task 5).
2. **Solar noon with the sun in the north** (Hà Nội in June): mood blending must not jump when the sun passes its highest point. Covered by `blends without jumps through a June and a December day` (Task 3).
3. **Small prototypes** (short side 2.5 m, the minimum `isPrototypeCandidate` accepts): bevels must not invert the geometry. Covered by `clamps the radius on tiny houses` (Task 5).
4. **A mood that never happens at the place and date** (e.g. no golden hour under the midnight sun): the picker must still set a valid clock. Covered by `returns a valid minute when the mood never occurs` (Task 3).
5. **Old links and old browser state** (`?style=mono`, localStorage `tinymap:colorMode`): the page opens normally and ignores them. Covered by Task 1 Step 4.

**Interfaces:**
- Consumes: `sunState(date, lat, lon): SunState` from `src/scene/sun.ts`
- Produces:
  - `type Mood = 'morning' | 'noon' | 'golden' | 'night'` (A, B, C, D)
  - `MOODS: readonly Mood[]` = `['morning', 'noon', 'golden', 'night']`
  - `MOOD_LABEL: Record<Mood, string>` = `{ morning: 'Buổi sáng', noon: 'Nắng trưa', golden: 'Hoàng hôn', night: 'Đêm ấm' }`
  - `interface MoodKey { sky: string; sun: string; sunIntensity: number; hemiSky: string; hemiGround: string; hemiIntensity: number; exposure: number }`
  - `MOOD_KEYS: Record<Mood, MoodKey>`: the values from spec §10 (A `#a9d8f2`/`#ffffff` 2.0/`#cfe3ff` `#e0d4b8` 1.6/1.0; B `#cdeaf3`/`#fff0d8` 1.9/`#e3f0ff` `#f0dcc0` 1.7/1.05; C `#f8cfab`/`#ffb36b` 2.6/`#ffe0c2` `#c4b0d4` 1.2/1.0; D `#7a76a8`/`#a9b0ff` 0.6/`#9692cc` `#4a4160` 0.9/1.1)
  - `moodWeights(s: SunState, rising: boolean): Record<Mood, number>`: the weights sum to 1
  - `isRising(date: Date, lat: number, lon: number): boolean`: true when the altitude 10 minutes later is higher
  - `moodLighting(s: SunState, rising: boolean, cloud?: number): { sky: THREE.Color; sunColor: THREE.Color; sunIntensity: number; hemiSky: THREE.Color; hemiGround: THREE.Color; hemiIntensity: number; exposure: number }`: a weighted blend of `MOOD_KEYS`, then the existing cloud greying (`sky.lerp('#9aa3ad', cloud * 0.45 * (1 - night))`, sun intensity `× (1 - cloud * 0.6)`)
  - `dominantMood(s: SunState, rising: boolean): Mood`
  - `minuteForMood(mood: Mood, dateUtcMidnight: Date, lat: number, lon: number, utcOffsetHours: number): number`: a local clock minute in 0..1439

Weights (`elev = sin(altitude)`, `d = 1 − s.night`, `smooth` as in `sun.ts`):

```
rising:  morning = d · (1 − smooth(0.30, 0.60, elev)), noon = d − morning, golden = 0
falling: golden  = d · (1 − smooth(0.12, 0.35, elev)), noon = d − golden,  morning = 0
night = s.night
```

Noon fills the gap where `elev ≥ 0.6`, so the rising/falling switch at solar noon is seamless while noon elevation is ≥ 0.6. That holds all year across Vietnam. In code, mark it as `// ponytail: assumes noon sun ≥ 37°; key on hour angle if the app goes beyond ~30° latitude`.

`minuteForMood` scans the day in 5-minute steps and returns the minute where the mood's weight is highest. Ties go to the earliest minute, except for `night`, where it is the first minute at least 60 minutes after sunset. If the mood never gets a weight above 0.05, it returns noon (720) for `noon`, `morning` and `golden`, and 0 for `night`.

import { describe, expect, it } from 'vitest';
import { sunState } from '../src/scene/sun';
import { dominantMood, isRising, minuteForMood, moodLighting, moodWeights, MOODS } from '../src/scene/moods';

const HN = { lat: 21.0285, lon: 105.8542 };
const at = (y: number, m: number, d: number, minLocal: number) => new Date(Date.UTC(y, m - 1, d, 0, minLocal) - 7 * 3_600_000);
const state = (date: Date) => [sunState(date, HN.lat, HN.lon), isRising(date, HN.lat, HN.lon)] as const;

describe('moods', () => {
  it('weights sum to 1 and pick the expected mood through a day', () => {
    for (let m = 0; m < 1440; m += 15) {
      const w = moodWeights(...state(at(2026, 6, 21, m)));
      expect(MOODS.reduce((a, k) => a + w[k], 0)).toBeCloseTo(1, 5);
    }
    expect(dominantMood(...state(at(2026, 6, 21, 12 * 60)))).toBe('noon');
    expect(dominantMood(...state(at(2026, 6, 21, 7 * 60)))).toBe('morning');
    expect(dominantMood(...state(at(2026, 6, 21, 18 * 60 + 15)))).toBe('golden');
    expect(dominantMood(...state(at(2026, 6, 21, 22 * 60)))).toBe('night');
  });
  it('blends without jumps through a June and a December day', () => {
    for (const [y, mo, d] of [[2026, 6, 21], [2026, 12, 21]]) {
      let prev = moodLighting(...state(at(y, mo, d, 0)));
      for (let m = 1; m < 1440; m++) {
        const cur = moodLighting(...state(at(y, mo, d, m)));
        // Dusk in the tropics lasts ~25 min, so a per-minute step up to ~0.05 is a fade; a jump is ≥ 0.3.
        expect(Math.abs(cur.sky.r - prev.sky.r) + Math.abs(cur.sky.g - prev.sky.g) + Math.abs(cur.sky.b - prev.sky.b)).toBeLessThan(0.08);
        expect(Math.abs(cur.sunIntensity - prev.sunIntensity)).toBeLessThan(0.05);
        prev = cur;
      }
    }
  });
  it('puts golden hour shortly before sunset in December and in June', () => {
    for (const [mo, sunsetMin] of [[12, 17 * 60 + 20], [6, 18 * 60 + 45]]) {
      const g = minuteForMood('golden', new Date(Date.UTC(2026, mo - 1, 21)), HN.lat, HN.lon, 7);
      expect(g).toBeGreaterThan(sunsetMin - 90);
      expect(g).toBeLessThan(sunsetMin);
    }
  });
  it('returns a valid minute when the mood never occurs', () => {
    const m = minuteForMood('golden', new Date(Date.UTC(2026, 5, 21)), 78.2, 15.6, 1); // Svalbard, midnight sun
    expect(m).toBeGreaterThanOrEqual(0);
    expect(m).toBeLessThan(1440);
  });
});

  - `placeToyVertex(corner: THREE.Vector3, offset: THREE.Vector3, size: THREE.Vector3, out?: THREE.Vector3): THREE.Vector3`. It returns `corner × (size/2 − r) + offset`, per axis, where `r` is that vertex's bevel radius clamped to `0.45 × min(size.x, size.z)`. The same formula goes in GLSL; keep the two side by side in comments.
  - `toyWallsUnit(): THREE.BufferGeometry`: plinth (true footprint, `plinthH` tall, colour × `PLINTH_SHADE` baked into the vertex colour) plus a body inset by `inset` with rounded vertical edges and a rounded top edge. Attributes: `position` (unit-box position, for bounds), `aCorner` (vec3 of −1/0/+1 per axis; `y` 0 = bottom, 1 = top anchor), `aOffset` (vec3, metres), `normal`.
  - `toyFlatRoofUnit()`: a slab 0.9 m thick, rounded, ending at the footprint edge.
  - `toyPitchedRoofUnit(hipped: boolean)`: thick bevelled ridge and eaves, plus a chimney (`aChimney = 1` on its vertices, 0 elsewhere) on gabled roofs.
  - `bakeToyInstance(geo: THREE.BufferGeometry, matrix: THREE.Matrix4): THREE.BufferGeometry`: CPU placement via `placeToyVertex`, then the instance rotation and translation. Used by Task 8.
- Shader (`toyProto: true` only):
  - before `#include <project_vertex>`: `vec3 s = vec3(length(instanceMatrix[0].xyz), length(instanceMatrix[1].xyz), length(instanceMatrix[2].xyz));` then `transformed` is set from `aCorner`, `aOffset` and `s` so that after `instanceMatrix` the vertex lands at `placeToyVertex` (that is, `transformed = (aCorner × (s/2 − r) + aOffset) / s`);
  - normals: `objectNormal /= s` before instancing, then normalise;
  - chimneys: vertices with `aChimney > 0.5` collapse to the roof centre when `fract(aSeed * 13.0) > 0.6`, so about 40% of gabled roofs have one;
  - prototype materials use `flatShading: false`.
- Prototype instance matrices (`PrototypeCollector.build`):
  - walls: scale `(w, height, l)`;
  - flat roof: scale `(w, 1, l)` at `y = height`;
  - pitched roof: scale `(w, rise, l)` at `y = height`.
  - The old `+ 0.7` eave overhang is removed, because overhang now lives in `aOffset` and stays within the footprint.
  - The draw-call count stays the same: still at most 4 prototype meshes.
